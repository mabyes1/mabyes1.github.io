How I work with AI

How I work with AI

I own the scope and acceptance bar, let agents carry the implementation, and let real devices and data decide.

  1. 01

    Define scope and acceptance first

    Before writing code, I pin down who operates it, what must work, and which settings and data must survive. Cheap, reversible changes come first so the results steer the next move.

    ExampleFor my RL agent, acceptance meant win rate over blocks of live fights—never one lucky fight.

  2. 02

    Let agents carry the implementation

    I work with Claude Code, Codex, and Gemini on implementation, analysis, or review depending on the task, turning recurring workflows into tools or skills.

    ExampleOn PicoBridge, agents wrote much of the cross-stack code across a Windows driver, C# desktop app, and Android, while I focused on Bluetooth standby and clipboard behavior.

  3. 03

    Verify on real devices and data

    A command returning OK, a clean install, and a tool that feels right in daily use are three different milestones. I test on my own phone, head unit, peripherals, and live games—if it stalls in practice, it isn’t done.

    ExamplePicoCar reported success setting the default launcher, yet the physical HOME button still opened the factory UI. I tracked down the vendor setting, fixed it, and tested the actual button.
