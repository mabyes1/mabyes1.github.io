AI Agent 與 MCP2025–2026

coding-tools MCP

自己日常開發用的 AI 協作底座：讓雲端對話型 AI 在核准的路徑內操作本機檔案、終端機、Git 與手機裝置；真的卡住要人看一眼或點一下時，就透過 human_help_me 把最小步驟交給我。

Why

為什麼做

雲端 AI 寫得出程式，卻碰不到我真正的工作目錄、開發環境跟手機。我想讓它能直接在我這台 Windows 上接手做事，需要我確認時再精準把我叫回來。

What I built

我做了什麼

  • Filesystem、shell、execution session、Git 與 workspace 操作橋接；透過 ADB 在實機安裝、看 log、截圖。
  • Session 生命週期、健康檢查和環境自省，讓模型分得出「指令壞了、MCP 壞了、主機不在，還是 session 爆了」。
  • human_help_me 獨立成一個 MCP：瀏覽器擴充會在 ChatGPT、Claude、Gemini 網頁上把畫面模糊等我回應，5 秒沒反應就改跳系統對話框。

Engineering

我碰到的工程問題

  • 跑指令要能接續 session 也能取消；前景 HTTP 請求結束跟背景程序還在跑，是兩回事。
  • Windows service、使用者登入桌面和瀏覽器各自隔離；安裝、更新與跳出求助視窗都得對準實際操作中的使用者階段。
  • 安裝程式會自己找出 Python、建好服務環境並留住原本的 tunnel 設定，管理頁也能直接看健康狀態、更新或回復。

Role & AI

我和 AI 怎麼分工

每天跟 AI 協作發現缺什麼功能就直接補進去，實作與 coding agents 一起完成，再拿真實工作目錄與實機除錯把行為調順。

Trade-offs

實測後推翻與取捨

  • 用久了才體會，工具越多不代表越強；模型要清楚什麼時候該用、什麼時候停、什麼時候叫人接手。

Outcome

成果

每天開發仰賴的本機工具層，包辦 Windows 服務安裝更新、健康管理介面和獨立的 human_help_me 求助入口。
