系統與裝置2026

PicoBridge

讓桌上同一套 Windows 鍵鼠直接切到手機和另一台電腦上用，連剪貼簿跟檔案一起帶過去。從早期 ESP32-S3 硬體橋接一路做到 Windows 原生藍牙 HID 驅動、桌面程式和 Android App，追求的是每天切來切去依然穩。

Why

為什麼做

只想用桌上原本的鍵鼠順手操作手機，回電腦時又能把剛複製的內容一起帶回來。打字會通只是起步，真正磨人的是藍牙待命干擾音訊、剪貼簿歸屬，還有更新後認不認得原裝置。

What I built

我做了什麼

  • C# 桌面程式、C 寫的 Windows 驅動（測試簽章）、Java Android App，以及 PowerShell 建置、簽章與發佈腳本。
  • 單一離線安裝檔，支援原地更新與回滾；在 Galaxy S23 與第二台電腦上日常實測。
  • 前身是自己焊的 ESP32-S3 硬體版：同時連 3 台藍牙主機，還兼當 USB 麥克風與喇叭。

Engineering

我碰到的工程問題

  • 閒置沒操作時卻害手機藍牙音訊斷斷續續。一路追 HCI 封包查到 HID 鍵盤燈號回報，改掉 descriptor 後保住連線待命，再用手機實播音樂確認改善。
  • 剪貼簿會分清楚「電腦帶過去的」跟「在手機上新複製的」，回電腦只帶回新內容，才不會拿舊圖片或回聲資料把電腦工作蓋掉。
  • 桌面閃爍原本以為是動畫 bug，翻錄影畫面逐幀抓到同步時有個隱藏清單瞬間跳出來；修掉可見性後實機消失。
  • Windows 與 Android 更新都會保留裝置身分、配對與設定，並留著可回退的舊版，修一個問題不用整套重配對。

Role & AI

我和 AI 怎麼分工

切換手感與穩定度門檻由我親自把關，每天在主力 Windows、Galaxy 手機跟第二台電腦上重度使用；跨 C 驅動、C# 桌面端和 Android 的大量實作則與 Codex 等 agents 協力推進。

Trade-offs

實測後推翻與取捨

  • 鍵鼠輸入走 Bluetooth Classic HID，合併版 Android App 的剪貼簿和傳檔走區網；兩條通道狀態各自顯示與重連，排錯一眼就能看清。
  • 自寫 Windows 驅動採測試簽章，搭配單一離線安裝與回滾腳本，專注把自家主力開發機與筆電的日常切換做到最穩。

Outcome

成果

已在日常主力環境穩定服役，涵蓋鍵鼠切換、音訊共存與剪貼簿回傳；每次發版都保留舊版回退與雙端實測紀錄。
