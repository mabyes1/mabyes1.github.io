AI Agent 與 MCP2026

CLI Monitor v2

我每天在用的 AI coding 控制台：把 Codex、Claude、OpenCode、PI、AGY 等 AI CLI 統一接到 Web、Discord 和 Telegram，人不在電腦前也能看畫面、下指令、處理異常。

Why

為什麼做

一開始只是想離開座位時還能操作 AI CLI。真正天天用才發現，難的是保住 PTY 畫面、原生 session、佇列、權限與排程狀態，讓我隨時從手機或電腦無縫接手。

What I built

我做了什麼

  • 吸收各家 CLI 在畫面、輸入、回覆格式與完成判定上的差異；每個 instance 各自保留 PTY 與原生 session。
  • Discord／Telegram 轉送與長訊息分段、FIFO 佇列、忙碌保護、逾時處理、session 恢復與附件傳送。
  • Web Control Hub：看即時畫面、中文輸入、主從／並列模式、手動接管；分頁閒置時自動降低更新頻率。
  • PM2 服務管理與 Cron 排程管理器，只允許操作程式碼裡定義好的服務。

Engineering

我碰到的工程問題

  • 送出提示後畫面有在動，不代表已經跑完；必須抓準忙碌中、等輸入和原生 session 接續，才不會讓下一則訊息直接插斷上一個任務。
  • Web、Discord 與 Telegram 共用同一個執行中的 CLI 狀態，人不在電腦前也能接手原本進度，不用另外開一段失去上下文的新對話。

Role & AI

我和 AI 怎麼分工

每天實戰碰到的卡頓和誤觸，直接變成這套系統的狀態規則與保護邊界；TypeScript 主體與測試多由 coding agents 接手實作。

Trade-offs

實測後推翻與取捨

  • 刻意保留各 CLI 原生的 stateful session，不硬包成 OpenAI-compatible API；整合比較費工，但功能完整，也比較不會踩到供應商規範。

Outcome

成果

主程式留在私人 repo，另外整理了一個去識別化的公開 repo，放架構圖跟可以直接點的互動 demo。
